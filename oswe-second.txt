## 🔎 Findings — vulnerabilities (file + exact line numbers)
File: input.ts (original version)
1. Lines 42  
   - Vulnerability: Synchronous PBKDF2 call (crypto.pbkdf2Sync)  
   - Severity: High  
   - Why: Blocking a CPU-bound operation on the event loop can cause DoS or degrade service responsiveness.

2. Lines 36–37  
   - Vulnerability: No minimum PBKDF2 iterations (weak hash parameters)  
   - Severity: High  
   - Why: If stored hashes use very low iteration counts, they are easier to brute force.

3. Lines 55, 60–61  
   - Vulnerability: Username enumeration via timing side-channel  
   - Severity: Medium  
   - Why: The function returned early for wrong usernames but waited doing expensive work for valid usernames — this difference in timing can reveal valid usernames.

4. Lines 4–7  
   - Vulnerability: Environment variable name leaked in thrown error message  
   - Severity: Medium  
   - Why: Error messages containing exact missing variable names may leak internal configuration details via logs or error reports.

5. Lines 19–21  
   - Vulnerability: Unsanitized PRIVATE_KEY_PATH returned directly  
   - Severity: Medium  
   - Why: Returning raw env path shapes can allow unintended path traversal/usage by callers; private keys should be loaded from secure sources or validated.
